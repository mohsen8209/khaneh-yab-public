# خانه‌یاب عمومی دیوار

این پوشه نسخه‌ی مستقل توسعه‌ی خانه‌یاب عمومی است. کد پایه و بانک محله را از خانه‌یاب شخصی گرفته، اما تنظیمات، دیتابیس، بازخوردها، مدل سلیقه، خروجی‌ها، لاگ‌ها و پورت اجرای خودش را دارد. تغییرات این پوشه نباید به پوشه‌ی والد وابستگی نوشتنی داشته باشند.

امکانات نسخه شخصی به‌عنوان نقطه شروع حفظ شده‌اند، اما این نسخه اکنون حساب کاربری، نشست امن، تأیید مدیر و داده‌های سلیقه‌ای مجزا برای هر کاربر دارد. موجودی آگهی‌ها داده عمومی مشترک است؛ بازخوردها، مقایسه‌ها و مدل یادگیری هر حساب فقط به همان کاربر تعلق دارند.

## نقشه معماری زنده

پیش از توسعه، [ARCHITECTURE.md](ARCHITECTURE.md) را بخوان. این سند شامل Mermaid جریان‌ها، Routeهای استخراج‌شده از AST، Schema واقعی SQLite، مسئولیت ماژول‌ها و راهنمای اثر تغییر است. `AGENTS.md` عامل‌های بعدی را ملزم به خواندن و بازبینی آن می‌کند و تست معماری اجازه کهنه‌شدن بی‌صدای نقشه را نمی‌دهد.

```powershell
python scripts/update_architecture.py --check
python scripts/update_architecture.py --write
```

## استقرار روی چابکان

روش اصلی استقرار فعلی، CLI چابکان است. پروژه با `start.sh`، پورت `8766`، کش بسته‌های
Python و SQLite روی مسیر دائمی مستقل آماده شده است. مراحل دقیق ورود با توکن، اولین
Deploy، ساخت مسیر دائمی و تست سلامت در [DEPLOY_CHABOKAN.md](DEPLOY_CHABOKAN.md) است.

در production فقط یک نمونه سرویس اجرا کنید. SQLite در این مقیاس به سرویس دیتابیس
جدا نیاز ندارد؛ چند نمونه تنها پس از مهاجرت برنامه‌ریزی‌شده به PostgreSQL مجاز است.

## استقرار روی پارس‌پک

نسخه عمومی برای Python PaaS با `app.py`، `requirements.txt`، اسکن پس‌زمینه، ادمین
بوت‌استرپ‌شده از Secret و SQLite روی Volume دائمی آماده شده است. قرارداد کامل پنل،
متغیرهای محیطی و انتقال امن دیتابیس در [DEPLOY_PARSPACK.md](DEPLOY_PARSPACK.md) است.

در پارس‌پک فقط یک Pod اجرا کنید.

## مدل رتبه‌بندی

گروه‌های کیفی محله فقط برای توضیح و نمایش‌اند. امتیاز مکانی از نگاشت مستقل
`individual_scores` خوانده می‌شود؛ هر ۴۵۳ ورودی رسمی تهران در دیوار امتیاز مخصوص و یکتای خودش را دارد و
حتی محله‌های داخل یک گروه نیز نسبت به یکدیگر مرتب شده‌اند. برنامه در صورت کمبود یا
اضافه‌بودن امتیاز یک محله اجرا نمی‌شود تا ناخواسته به نمره گروهی برنگردد.

- محله و ریزموقعیت: ۸ امتیاز
- ارزش اجاره نسبت به فایل‌های مشابه: ۵ امتیاز
- مشخصات ملک: ۳ امتیاز
- اعتبار آگهی: ۳ امتیاز
- تازگی: ۱ امتیاز

نمره نهایی به‌تنهایی برای اعلان کافی نیست. اعتبار آگهی باید حداقل ۷۵٪ و اطمینان مکانی حداقل ۷۰٪ باشد. هم‌خانه، اجاره اتاق، خوابگاه و پانسیون با املاهای رایج مختلف، پارکینگ موتور، واحد زیرهمکف، عکس تزئینی یا نامرتبط و آگهی دارای صفر یا یک عکس پیش از رتبه‌بندی کاملاً الک می‌شوند. این موارد در تب «همه»، آمار، مقایسه سلیقه یا اعلان حضور ندارند. محله‌های پایین‌تر از حد تنظیم‌شده و خانه‌های واقعی اما نامناسب همچنان در بخش ردشده قابل بررسی‌اند.

رتبه‌های محله در [data/tehran_neighborhoods.json](data/tehran_neighborhoods.json) قرار دارند. بانک نسخه ۳ تمام ۴۵۳ نام رسمی فعلی دیوار در تهران را با شناسه، اسلاگ، مختصات مرکز، پهنه جغرافیایی، نوع مکان، نمره، گروه و سطح اطمینان پوشش می‌دهد. ۱۴۵ نمره قبلی بدون تغییر حفظ شده‌اند؛ محله‌های مهم جاافتاده کالیبراسیون دستی دارند و ریزنام‌های باقی‌مانده با برچسب شفاف `medium` یا `provisional` از نقاط کالیبره‌شده نزدیک برآورد شده‌اند. این رتبه پایه عمومی و ثابت است، به سلیقه کاربر وابسته نیست و ادعای امنیت یا کیفیت یکسان تمام خیابان‌های محله را ندارد.

اسنپ‌شات فهرست رسمی در [data/divar_tehran_districts.json](data/divar_tehran_districts.json) نگهداری می‌شود. ابزار [scripts/build_neighborhood_atlas.py](scripts/build_neighborhood_atlas.py) بانک را به‌شکل قطعی بازسازی می‌کند و هر اختلاف در تعداد، شناسه، نام، اسلاگ، نمره یا گروه باعث خطای اعتبارسنجی می‌شود.

## حساب‌ها و تأیید مدیر

ثبت‌نام عمومی است، اما حساب تازه با وضعیت `pending` ساخته می‌شود و تا زمان تأیید روت‌ادمین به داشبورد و APIهای کاربردی دسترسی ندارد. پنل مدیریت در `http://127.0.0.1:8766/admin` قرار دارد و فقط نقش `admin` می‌تواند آن را باز کند. تأیید، رد و تعلیق حساب در گزارش ممیزی ثبت می‌شوند؛ تعلیق یا رد، همه نشست‌های فعال آن کاربر را همان لحظه باطل می‌کند.

کاربر تازه پس از اولین ثبت معیارهای جست‌وجو، ۱۲ مقایسه اجباری و بدون گزینه ردکردن انجام می‌دهد. هر زوج از آگهی‌های فعال، غیر اسپم و منطبق با خط قرمزهای همان کاربر انتخاب می‌شود و سامانه پیش از شروع، وجود زوج‌های یکتای کافی برای کامل‌کردن هر ۱۲ مرحله را کنترل می‌کند. زوج باز در رفرش ثابت می‌ماند، هر پاسخ فقط یک‌بار ثبت می‌شود و تا تکمیل مرحله، داشبورد از مسیر یا API قابل دورزدن نیست. کاربران کامل‌شده قدیمی در زمان ارتقا ناگهان پشت این مرحله قفل نمی‌شوند.

رمزها با `scrypt` و salt تصادفی ذخیره می‌شوند و توکن خام نشست وارد دیتابیس نمی‌شود. درخواست‌های تغییردهنده نیز به CSRF token نیاز دارند. برای ساخت یا بازیابی روت‌ادمین از فرمان تعاملی زیر استفاده کن تا رمز در تاریخچه ترمینال ثبت نشود:

```powershell
python -m divar_scout admin-create --username root --display-name "مدیر اصلی"
```

## اجرا

پروژه به Python 3.11 یا جدیدتر نیاز دارد. مدل یادگیری شخصی با پیاده‌سازی سبک
داخلی اجرا می‌شود و وابستگی سنگین جداگانه ندارد:

```powershell
python -m pip install -e .
```

```powershell
# تست‌ها
python -m unittest discover -s tests -v

# یک اسکن کنترل‌شده
python -m divar_scout scan --detail-limit 10

# داشبورد محلی
python -m divar_scout dashboard

# پایش دائم با فاصله زمانی config.json
python -m divar_scout watch
```

### تست واقعی API پروداکشن

این تست با یک حساب تأییدشده وارد می‌شود، اسکن واقعی همان پروفایل را تا پایان دنبال
می‌کند، قابل‌استفاده‌بودن خروجی و ظرفیت ۱۲ مقایسه یکتا را می‌سنجد و خانه‌های برگشتی
را مستقلاً با بودجه، متراژ، خواب، سن، امکانات اجباری، محله، عکس و لینک دیوار تطبیق
می‌دهد. رمز در مخزن ذخیره نمی‌شود و نشست آزمایشی در پایان logout می‌شود.

```bash
export KHANEYAB_SMOKE_USERNAME="your-approved-user"
read -s -p "Password: " KHANEYAB_SMOKE_PASSWORD; echo
export KHANEYAB_SMOKE_PASSWORD
python scripts/smoke_production.py --expected-release 0.1.13
unset KHANEYAB_SMOKE_PASSWORD
```

گزینه `--read-only` فقط سلامت، ورود، پروفایل و موجودی فعلی مقایسه را کنترل می‌کند و
اسکن جدیدی شروع نمی‌کند.

داشبورد عمومی در `http://127.0.0.1:8766` باز می‌شود. فایل‌های `start_dashboard.cmd`، `scan_once.cmd` و `watch.cmd` ابتدا از محیط `.venv` همین پوشه استفاده می‌کنند و میان‌برهای ویندوز هستند.

برای اجرای جداگانه هر دو نسخه در دو ترمینال VS Code:

```powershell
# ترمینال اول: نسخه شخصی روی 8765
cd C:\Users\Mohsen\Desktop\divar
.\start_dashboard.cmd
```

```powershell
# ترمینال دوم: نسخه عمومی روی 8766
cd C:\Users\Mohsen\Desktop\divar\public-house-finder
.\start_dashboard.cmd
```

- شخصی: `http://127.0.0.1:8765`
- عمومی: `http://127.0.0.1:8766`
- مدیریت عمومی: `http://127.0.0.1:8766/admin`

هر اسکن موفق، فهرست فعال دیوار را با دیتابیس همگام می‌کند. آگهی‌هایی که دیگر
در خروجی فیلتر نیستند فوراً از داشبورد، آمار و مقایسه‌ها کنار می‌روند؛ رکورد
تاریخی و بازخوردشان برای حافظه مدل حفظ می‌شود و در صورت بازگشت خودکار فعال
خواهند شد. پاسخ خالی یا خطای شبکه هیچ آگهی‌ای را دسته‌جمعی آرشیو نمی‌کند.

## یادگیری شخصی

داشبورد سه نوع بازخورد «پسندیدم»، «برای بازدید مناسبه» و «رد» را همراه با
دلیل ذخیره می‌کند. مقایسه دوتایی دو فایل نزدیک به هم را نمایش می‌دهد و سیگنال
قوی‌تری برای رتبه‌بندی می‌سازد. مدل Pairwise Logistic Regression کاملاً محلی
آموزش می‌بیند و ضرایب نسخه‌بندی‌شده آن به‌صورت JSON در SQLite ذخیره می‌شوند.
رد مستقیم یک آگهی همان لحظه آن را به بخش ردشده می‌فرستد و اعلان بعدی همان فایل
را مسدود می‌کند؛ نمره پایه برای تحلیل و آموزش مدل حفظ می‌شود. مرتب‌سازی انتخابی همیشه
اولویت مطلق دارد و آگهی ردشده نیز در جای واقعی خود بر اساس زمان، قیمت یا معیار منتخب دیده می‌شود.

مرتب‌سازی تازه‌ترین و قدیمی‌ترین از تاریخ واقعی «انتشار آگهی» در جزئیات دیوار استفاده
می‌کند. تاریخ «آخرین نردبان» جداگانه نگهداری می‌شود و به‌جای سن واقعی آگهی استفاده نمی‌شود.

۱۲ مقایسه آغازین همان ۱۲ سیگنال لازم برای شروع اثرگذاری مدل را فراهم می‌کنند. پس از آن یادگیری با مقایسه و بازخوردهای داخل داشبورد ادامه دارد؛ اثر مدل تدریجی است و در
۴۰ سیگنال به قدرت کامل می‌رسد. اصلاح شخصی حداکثر `±۲` امتیاز است و نمی‌تواند
رد سخت، ابهام مکانی یا الزامات پارکینگ و آسانسور را دور بزند. نمره پایه، مقدار
اصلاح، اطمینان مدل و علت تغییر جداگانه روی هر آگهی نمایش داده می‌شوند.

## اعلان گوشی با ntfy

فرمان `watch` هر ۱۰ دقیقه فیلتر را بررسی می‌کند. موجودی اولین اسکن به‌عنوان خط مبنا
بدون اعلان ثبت می‌شود؛ از اسکن بعد، آگهی‌های واقعاً تازه در اولویت دریافت جزئیات‌اند
و فقط در صورت رسیدن به آستانه نمره، اعتبار و اطمینان مکانی یک بار اعلان می‌شوند.
اجرای داشبورد به‌تنهایی پایش دوره‌ای را فعال نمی‌کند و برای اعلان دائم باید
`watch.cmd` یا `python -m divar_scout watch` در حال اجرا باشد.

1. برنامه ntfy را روی Android یا iOS نصب کن.
2. آدرس کانال را با دستور زیر ببین و همان را در برنامه Subscribe کن:

```powershell
python -m divar_scout topic
```

3. در [config.json](config.json) مقدار `notifications.enabled` را به `true` تغییر بده.
4. ارتباط را آزمایش کن:

```powershell
python -m divar_scout notify-test
```

توکن یا حساب کاربری لازم نیست. نام تصادفی کانال مانند رمز عمل می‌کند و نباید عمومی شود. پیام‌ها با `Cache: no` ارسال می‌شوند.

## داده و محدودیت مکانی

نسخه فعلی از داده عمومی مورد استفاده وب‌سایت دیوار بهره می‌گیرد و هیچ محدودیت دسترسی را دور نمی‌زند. جزئیات فقط برای آگهی‌های تازه و با تأخیر بین درخواست‌ها خوانده می‌شود. اگر ساختار وب‌سایت تغییر کند، کلاینت ممکن است نیاز به به‌روزرسانی داشته باشد.

دیوار برای بعضی فایل‌ها موقعیت `FUZZY` و شعاعی مانند ۵۰۰ متر برمی‌گرداند. خانه‌یاب این پین را آدرس قطعی فرض نمی‌کند؛ محله رسمی، پین، عنوان و آدرس داخل توضیحات را تطبیق می‌دهد و درصد اطمینان مکانی نمایش می‌دهد.

API رسمی «کنار دیوار» نیز جست‌وجو و دریافت آگهی را ارائه می‌کند، اما به API Key با مجوزهای `SEARCH_POST` و `GET_POST` نیاز دارد. در صورت دریافت کلید، مهاجرت کلاینت به API رسمی مسیر مناسب نسخه پایدارتر است.

## تنظیمات مهم

هر کاربر پس از تأیید مدیر، در ویزارد `/setup` شرایط خانه موردنظرش را کامل می‌کند. جست‌وجو همیشه از میان اجاره‌آپارتمان‌های تهران انجام می‌شود و هیچ لینک فیلتری از کاربر دریافت نمی‌شود. پاسخ‌های تأییدشده برای محدودکردن هوشمند اسکن دیوار به بودجه، متراژ، خواب، سن بنا، طبقه، تراکم ساختمان، امکانات و محله‌های انتخابی استفاده می‌شوند.

در اسکن درخواستی، هر کاربر فقط موجودی منطبق با پروفایل خودش را کرال می‌کند. به‌دلیل محدودیت Map API دیوار، انتخاب‌های بزرگ محله در قطعه‌های حداکثر ۱۵تایی فرستاده و بعد با شناسه آگهی ادغام می‌شوند؛ دو شناسه ناسازگار شناخته‌شده که کل فیلتر را بی‌صدا غیرفعال می‌کنند وارد درخواست نمی‌شوند. درخواست‌های هم‌زمان پروفایل‌های متفاوت در صف مستقل اجرا می‌شوند و داده یا بودجه بررسی جزئیات آن‌ها با یکدیگر مخلوط نمی‌شود.

بودجه ایده‌آل و قطعی، بازه استثنایی، متراژ، خواب، سن، طبقه، تراکم ساختمان و چهار امکان اصلی صریحاً پرسیده می‌شوند. کاربر می‌تواند همه تهران یا محله‌های مشخصی را انتخاب کند؛ در هر دو حالت امتیاز اختصاصی محله با سهم `8` از `20` بیشترین اثر را در نمره نهایی دارد و هیچ حد کیفی مبهمی از کاربر پرسیده نمی‌شود. همه بودجه‌های ذخیره‌شده بر حسب تومان‌اند و نرخ تبدیل پیش‌فرض ودیعه به اجاره ماهانه `0.03` است.

این نسخه هیچ مدل هوش مصنوعی یا تحلیل عکس اجرا نمی‌کند. کنترل عکس به قواعد قطعی و قابل توضیح محدود است: آگهی بدون عکس، تک‌عکس، عکس تزئینی/نمونه یا عکس تأییدشده به‌عنوان نامرتبط پیش از نمایش حذف می‌شود. یادگیری شخصی فقط از بازخوردها، دلایل و مقایسه‌های خود کاربر استفاده می‌کند.
